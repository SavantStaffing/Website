1 · Feed data sources

From job board to job feed

Every 15 minutes the scheduler starts the Job Scout on the employer that has gone longest without a scan. Each run passes through the same nine checks, in order. Temp partner listings arrive separately, as a snapshot with an expiry date.

2 · Layers of security

Five layers between a request and the data

A request has to clear each layer, from the outside in. The innermost layer is enforced by the database itself, so even a mistake in the website's code can't show one person's data to someone who shouldn't see it.

1Public edge

  • Encrypted connections only (HTTPS)
  • robots.txt and the Terms of Use bar scraping and AI training; AI crawlers are told to stay out
  • Guests see a six-role preview; employer ratings need an account

2Sign-in

  • Email and password with a verified address, or Google
  • New accounts are talent or recruiter; admin is never self-assigned
  • Coaches can only join with an invite code from an admin

3Role-guarded hubs

  • Each dashboard checks the role before it loads
  • A talent account can't open the recruiter or admin hub, and so on

4Server checks

  • Every server action re-verifies the session token
  • Inputs are checked against a schema before use
  • The database master key exists only on the server
  • Admin-only functions re-check the admin role
  • The scheduler needs a secret token to start a scan

5Row-level security

  • On every table: talent read and edit only their own rows
  • Recruiters see applications to their company's jobs only
  • API keys sit in a table no signed-in user can read

●Data protections

  • Résumés in private storage, shared by links that expire in 10 minutes
  • Demographic answers are never saved
  • Self-service account deletion, with a log that identifies no one
  • Ghost and scam filter keeps pay-to-apply listings out

+Savant Apply extension

  • Runs only on Greenhouse, Lever and Ashby application forms
  • Talks only to savantalent.com; only savantalent.com can talk to it
  • Downloads only the talent's own résumé link
  • Never submits an application

3 · Users & dashboards

Who sees what

Five kinds of user, each with its own hub. The table shows what the database lets each role read, which is the real limit regardless of what a page displays.

Guest

Anyone, no account

  • Home · About · Services
  • Jobs (six-role preview)
  • Employer Ratings (how it works)
  • Insights · Contact
  • Savant Apply guide
  • Terms · Privacy

Talent

Signs up as talent · /talent

  • Dashboard · Inbox
  • Job Feed · Temporary Work
  • Applications
  • Saved Answers
  • Account · Preferences · Settings
  • + Savant Apply extension

Recruiter

Signs up as recruiter · /recruiter

  • Dashboard · Inbox
  • Talent & Schedule
  • Talent Feed · Assigned Talent
  • Saved Talent
  • Jobs · Applications
  • Company · Account

Career coach

Invite code only · /coach

  • Service Requests (assigned) · Inbox
  • Talent & Schedule
  • Talent (assigned + request to coach)
  • Recruiters
  • Temp Partners
  • Settings

Admin

Granted by an admin · /admin

  • Dashboard · Inbox · Talent & Schedule
  • Talent assignments
  • Users · Coach invites · Organizations
  • Job Scout · Ratings · Unique scanners
  • Diagnostics · Jobs
  • Messages · Temp Partners · Settings

Assignments: an admin assigns talent to a recruiter or coach, or approves a coach's request to coach. While the assignment is active, that person sees the talent's full profile, contact details, job preferences and résumé; ending it removes access. New coaching sign-ups go to admins, who assign a coach.
